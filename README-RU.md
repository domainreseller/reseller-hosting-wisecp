# DNA Reseller Hosting

**Управляйте реселлерскими аккаунтами cPanel и Plesk из одного серверного модуля WiseCP.**

Один модуль, две панели. Тип панели вы не выбираете — модуль сам спрашивает сервер и запоминает,
какая панель ответила.

## ✨ Что умеет модуль

| Возможность | cPanel/WHM | Plesk |
|---|:---:|:---:|
| Проверка соединения и автоопределение панели | ✅ | ✅ |
| Создание аккаунта | ✅ | ✅ |
| Приостановка / возобновление | ✅ | ✅ |
| Удаление | ✅ | ✅ *(с проверкой принадлежности)* |
| Смена пароля | ✅ | ✅ |
| Смена пакета / плана | ✅ | ✅ |
| Синхронизация диска и трафика | ✅ | ✅ |
| Вход в клиентскую панель одним кликом | ✅ | ✅ |
| Вход одним кликом из админки | ✅ | ✅ |

> 💡 **Сделано для реселлеров.** Root или админ-доступ не нужен: модуль работает с правами вашего
> собственного реселлерского аккаунта, и каждый созданный аккаунт расходует вашу квоту.

---

## 📋 Требования

- **WiseCP** на вашем сервере, с доступом администратора
- **PHP** 7.4 – 8.4
- Расширения PHP: `curl`, `simplexml`
- **Реселлерский аккаунт cPanel/WHM** (токен WHM API) &nbsp;или&nbsp; **реселлерский аккаунт Plesk**
  (ключ API или пароль панели)
- Исходящий доступ с сервера WiseCP к серверу панели на API-порт панели

> ✅ Таблицы в базе не создаются, cron не нужен, зависимостей composer нет. Установка сводится к
> копированию папки.

## 🚀 Установка

### 1️⃣ Установите модуль

Скопируйте папку `DNAHosting` в каталог `coremio/modules/Servers/` вашей установки WiseCP.

```
wisecp/
└── coremio/
    └── modules/
        └── Servers/
            └── DNAHosting/     ← сюда
```

### 2️⃣ Добавьте сервер

**Products / Services → Hosting/Server → Shared Server Settings → Add New Shared Server**

| Поле | Что вводить |
|---|---|
| **Server Automation Type** | `DNAHosting` — это имя папки, в списке оно выглядит именно так |
| **IP Address** | Реальный адрес сервера панели; модуль подключается сюда |
| **Username** | Ваше реселлерское имя пользователя в этой панели |
| **Password** | Токен WHM API на cPanel, ключ API или пароль панели на Plesk |
| **Connect with SSL** | Включите |
| **Port** | `2087` для cPanel, `8443` для Plesk |

> ⚠️ **Поле Hostname вверху формы — это только подпись.** Модуль подключается по **IP Address**, а
> не по нему. В списке ваши серверы отображаются под этой подписью.

### 3️⃣ Проверьте соединение

Перед сохранением нажмите **Test Connection** или просто сохраните — WiseCP выполнит проверку сам.

Зелёный результат подтверждает и учётные данные, и определённую панель. При ошибке показывается
конкретный код HTTP или ошибка панели; см. [Логи и диагностика](#-логи-и-диагностика).

### 4️⃣ Создайте группу серверов

Если серверов несколько, создайте группу в **Shared Server Settings → Server Groups** и привяжите
продукт к группе, а не к одному серверу. Предлагается два типа распределения:

- **Всегда добавлять на наименее загруженный сервер.**
- **Заполнять один сервер полностью, затем переходить на наименее загруженный.**

Серверы переносятся между списками **Unassigned → Assigned** кнопками `Add` / `Remove`.

> ⚠️ **Держите группу однородной по панели.** Список пакетов в форме продукта берётся с **одного**
> выбранного в этот момент сервера. Если в группе есть и cPanel-, и Plesk-сервер, у выбранного
> имени пакета на другой панели может не оказаться соответствия, и заказ, попавший туда, завершится
> ошибкой *пакет не найден*.

### 5️⃣ Настройте продукт

**Products / Services → Hosting/Server → Web Hosting Packages** → откройте пакет → вкладка **Module
Settings**. В разделе **Server Selection** выберите **Single Server** или **Server Group** и
отметьте ваш сервер DNAHosting. После этого модуль отрисовывает собственные поля:

| Настройка | Значение |
|---|---|
| **Detected panel** | Панель, действительно найденная на этом сервере, например `cPanel / WHM`. Ошибка здесь означает, что определение не удалось |
| **Package / Plan** | Список пакетов, загружаемый с этого сервера в реальном времени |
| **Automatic Setup** | Включено: заказ разворачивается автоматически. Выключено: требуется подтверждение администратора |

> 💡 **О префиксе пакета на cPanel можно не думать.** Для пакета, который в панели виден как
> `bakcay328_paket2`, модуль сам разрешает префикс `имяпользователя_`. На Plesk список — это каждый
> сервисный план, определённый на сервере.

**Сохраните — модуль готов к работе.** 🎉

**‼️С этого момента вы управляете реселлерскими аккаунтами cPanel и Plesk через модуль во всех процессах WiseCP. Создание, приостановка и удаление полностью подчинены WiseCP.**

## 🔍 Логи и диагностика

**Tools → Logs → Module Logs**

| Лог | Когда пишется | Что содержит |
|---|---|---|
| **Module Logs**<br>*Tools → Logs → Module Logs* | Только при включённой функции **Module Logs** | Каждый запрос к панели и полученный ответ с меткой имени операции, например `createacct` или `webspace.add` |

> 💡 Переключатель находится вверху той же страницы. Включите его перед воспроизведением проблемы и
> выключите после.

> 🔐 Токен API или пароль сервера, любые пароли аккаунтов, созданные или изменённые модулем, и
> токены SSO-сессий — и в запросе, и в ответе — маскируются символами `***` **до того, как
> что-либо будет записано**.

### Частые ошибки

| Симптом | Причина и решение |
|---|---|
| `HTTP 403` либо обёртка `cpanelresult` в тексте ошибки | У реселлера, которому принадлежит токен, нет прав уровня WHM на этот вызов. В **WHM → Resellers → Edit Reseller's ACL List** выдайте права на список аккаунтов, создание, приостановку, удаление, пароль, апгрейд пакета, список пакетов, трафик и создание сессии, затем перевыпустите токен **под входом от имени этого реселлера** в **WHM → Development → Manage API Tokens** |
| Plesk **11003** | Ключ API выпущен для другого IP — выпустите новый для адреса, с которого подключается WiseCP, либо впишите пароль панели в поле Password |
| Plesk **1014** | Plesk отклонил тело запроса для версии XML-API, на которой говорит этот сервер. Убедитесь, что используете актуальную версию модуля; лог модуля называет спорный элемент |
| Вместо списка пакетов в форме продукта — текст ошибки | Определение панели или запрос пакетов не удался; причина написана в той же строке |

> 💡 Любая другая HTTP-ошибка приходит с текстовой выжимкой из тела ответа панели — голый код
> состояния никогда не вся история.

## 🧩 Что полезно знать

<details>
<summary><b>Различия панелей</b></summary>

<br>

- **Удаление на Plesk проверяет принадлежность.** Каждый открытый модулем аккаунт помечается
  внутренним идентификатором; метка проверяется перед любой операцией, поэтому модуль невозможно
  направить на подписку, созданную в панели вручную.
- **Смена домена работающей услуги на Plesk отклоняется.** Подписка Plesk находится по домену,
  поэтому изменение навсегда сломало бы все последующие операции. На cPanel домен редактируется;
  аккаунт продолжает обслуживать прежний домен, пока вы не измените его в панели.
- **Защита от дублирующихся доменов.** Удаление отклоняется, пока тот же домен всё ещё привязан к
  другой активной или приостановленной услуге на том же сервере.

</details>

<details>
<summary><b>Определение панели</b></summary>

<br>

Тип панели нигде не настраивается. При первом вызове модуль опрашивает сервер и запоминает, какая
панель ответила.

Порт решает только, какую панель пробовать **первой**: `8443` и `8880` сначала пробуют Plesk, любое
другое значение — cPanel. Само решение всегда приходит из настоящего вызова API, а вторая панель
пробуется, если первая догадка не ответила. Неверный порт замедляет определение, но не ломает его.

</details>

<details>
<summary><b>Учётные данные</b></summary>

<br>

Обе панели принимают учётные данные в поле **Password**, которое WiseCP хранит в зашифрованном
виде. Поле **Access Hash** этот модуль не использует никогда, и на серверах DNAHosting оно не
показывается.

На Plesk модуль сначала пробует значение как ключ API и сам откатывается к HTTP basic auth —
говорить ему, что именно вы ввели, не нужно.

</details>

<details>
<summary><b>Вне области применения</b></summary>

<br>

Управление почтовыми ящиками и пересылками, продажа реселлерских аккаунтов, импорт существующих
аккаунтов в WiseCP и кнопка *вход в root-панель* в админке. Модуль хранит только **реселлерские**
учётные данные — не root — поэтому открывать ему нечего.

</details>
